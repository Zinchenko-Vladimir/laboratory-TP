# Лабораторная работа №12 — вариант 4 (базовый)
**Вход в кабинет преподавателя: отображение имени и роли после проверки**

Реализация: серверная сессия + cookie `HttpOnly; SameSite=Strict` (`Secure` включается переменной `SECURE=1` при HTTPS). Внешних зависимостей нет — только Node.js ≥ 18.


> **Как открыть без запуска чего-либо:** дважды щёлкните `index.html` в папке проекта. Приложение откроется в **демо-режиме**: серверная часть имитируется прямо в браузере (файл `public/mock-server.js`), поэтому ничего устанавливать и запускать не нужно. На странице при этом показывается жёлтая плашка. Это учебный **прототип**: в отчёте обязательно укажите, что скриншоты сделаны в демо-режиме с имитацией сервера, а настоящая серверная проверка реализована в `server.js` (запуск: `start.bat` или `npm start`, адрес http://localhost:3001).

Демо-режим лучше открывать в Chrome или Edge: он хранит состояние в sessionStorage, чтобы работало обновление страницы после входа.

## Запуск
```
npm start        # http://localhost:3001
npm test         # автотесты, пересоздаёт TEST_RESULTS.md
```

## Тестовые учётные записи (учебные, не настоящие)
| Логин | Пароль | Роль |
|---|---|---|
| teacher1 | Teacher#2026 | teacher |
| student1 | Student#2026 | student |

В репозитории хранятся только хеши паролей (scrypt + соль, `users.json`). Новый хеш: `node tools/hash.js <пароль>`.

## Схема
```
Браузер → POST /api/login → сервер проверяет логин/пароль → создаёт сессию, выдаёт cookie sid
        → GET /api/profile (cookie) → 200 {имя, роль} | 401
        → GET /api/teacher/groups  → 200 (teacher) | 403 (student) | 401 (без входа)
        → POST /api/logout → сессия уничтожена, cookie удалена
```

## Маршруты
| Метод и путь | Назначение | Ответы |
|---|---|---|
| POST /api/login | вход | 200, 400 (пустые поля), 401 (неверные данные) |
| GET /api/profile | профиль текущего пользователя | 200, 401 (в т.ч. session_expired) |
| GET /api/teacher/groups | защищённый ресурс преподавателя | 200, 401, 403 |
| POST /api/logout | выход | 200 |

Права проверяются на сервере; кнопки и сообщения в интерфейсе — только для удобства.

## Ограничения (учебный прототип)
- Сессии хранятся в памяти процесса и пропадают при перезапуске сервера.
- Нет ограничения числа попыток входа.
- Для реального использования нужен HTTPS (`SECURE=1`).
