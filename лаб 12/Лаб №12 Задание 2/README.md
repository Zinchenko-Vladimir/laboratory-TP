# Лабораторная работа №12 — вариант 14 (средний)
**Панель администратора: защита маршрута и проверка прав на сервере**

Реализация: серверная сессия, cookie `HttpOnly; SameSite=Strict`, скользящий тайм-аут бездействия (15 минут), роли `admin` / `user`. Зависимостей нет — только Node.js ≥ 18.


> **Как открыть без запуска чего-либо:** дважды щёлкните `index.html` в папке проекта. Приложение откроется в **демо-режиме**: серверная часть имитируется прямо в браузере (файл `public/mock-server.js`), поэтому ничего устанавливать и запускать не нужно. На странице при этом показывается жёлтая плашка. Это учебный **прототип**: в отчёте обязательно укажите, что скриншоты сделаны в демо-режиме с имитацией сервера, а настоящая серверная проверка реализована в `server.js` (запуск: `start.bat` или `npm start`, адрес http://localhost:3014).

Демо-режим лучше открывать в Chrome или Edge: он хранит состояние в sessionStorage, чтобы работало обновление страницы после входа.

## Запуск
```
npm start        # http://localhost:3014
npm test         # автотесты, пересоздаёт TEST_RESULTS.md
```

## Тестовые учётные записи (учебные, не настоящие)
| Логин | Пароль | Роль |
|---|---|---|
| admin | Admin#2026 | admin |
| user1 | User#2026 | user |
| user2 | User2#2026 | user |

Хранятся только хеши (scrypt + соль, `users.json`).

## Что защищено на сервере
| Ресурс | Без входа | Роль user | Роль admin |
|---|---|---|---|
| GET /admin (страница админки) | 401 | 403 | 200 |
| GET /api/admin/users | 401 | 403 | 200 |
| POST /api/admin/users/:login/block | 401 | 403 | 200 |

Файл админки лежит в `private/` и не отдаётся как статика: сервер выдаёт его только после проверки роли. Ссылка «Панель администратора» на главной скрывается для обычных пользователей лишь для удобства — реальная защита серверная.

Дополнительно: администратор может блокировать пользователей; при блокировке все его сессии закрываются сразу, повторный вход возвращает 403. Себя заблокировать нельзя.

## Схема
```
вход → проверка пароля → сессия + cookie → запрос ресурса
     → нет cookie: 401 | сессия истекла: 401 session_expired | роль не admin: 403 | иначе 200
выход → сессия удалена → тот же cookie больше не принимается (401)
```

## Ограничения (учебный прототип)
- Сессии и признак блокировки хранятся в памяти и сбрасываются при перезапуске.
- Нет ограничения числа попыток входа и журнала действий администратора.
- Для реального использования нужен HTTPS (`SECURE=1`).
